## 一、快速上手

| 入口 | 地址 |
|---|---|
| 体验 | https://bondpup.vercel.app |
| 快速评测 | https://bondpup.vercel.app/?demo=1 |
| MCP | https://bondpup.vercel.app/mcp |
| 健康检查 | https://bondpup.vercel.app/health |

带 `?demo=1` 直接进入已有示例数据的主页，无需填写问卷。评测机器人不走七步流程。

`/health` 返回当前部署的 commit hash，可与提交的 tag 核对。

### 三分钟路径

1. 主页可见四个罐子（生活 / 安心 / 梦想 / 未来）与小狗慢慢
2. 点「帮我看看要不要买」，输入任意物品与金额
3. 慢慢读取安心罐余额、引用你以前的相似决定，给出三个完全对等的动作：现在买 / 放到明天 / 这次先不买
4. 选任一动作，确认后写入状态
5. 进入「慢慢的小金库」，可见已确认的金钱原则卡

## 二、完整体验：七步起点流程

访问 https://bondpup.vercel.app 从零开始。

四个罐子的数字全部从你自己的回答推出来，不套用 50/30/20 之类的固定比例，不引用平均房租之类的参考值。整个流程的设计原则是「问由近到远，算由大到小」。

**第一步 · 起小名**
给小狗起个小名，默认「慢慢」。之后所有对话都用你起的名字，通过 `{alias}` 插值实现，代码里不硬编码角色名。

**第二步 · 问近期**
这个月想怎么过：想攒下来一点 / 想让自己过得舒服一些 / 有个想买的东西 / 我想自己说说。

自由输入永远是一个选项。选「有个想买的东西」直接衔接下一步。这一步给零基础用户台阶，不用组织语言也能开始。

**第三步 · 问远期**
有没有什么事是你想为它慢慢存一点钱的。可以跳过，跳过不影响后续任何环节。

选「有」之后追问三小项：它是什么、大概需要多少钱、希望什么时候实现。金额不确定时可填大概。

**第四步 · 拆解愿望**
慢慢把你说的整理成几件「在意的事」（3-4 条）。每条可改、可删、可加。

关键约束：**必须你点头，它才写下来。** 模型的输出在这一步只是候选，不是数据库真相。

**第五步 · 问钱**
三个数字：这个月大概能自己安排多少钱、有哪些是这个月一定要花的、之前有没有已经存下来的钱。

每项旁边都有「我还不确定」的入口，点了慢慢会说「不确定也没关系呀〜先空着，想起来了再填」。

第二项可展开一个纯加法清单：房租 / 水电燃气 / 通讯 / 交通 / 饮食 / 其他固定。每项可空，填几项算几项。

**这个清单不给任何参考值。** 不会出现「上海平均房租 3500」这类提示，空着就是空着——引用平均值等于替用户设定期待。

**第六步 · 倒推**
慢慢倒推目标月供：`max(0, 目标金额 − 已有) ÷ 剩余月数`，异常值由代码处理。

如果算出来压力大，它会说「如果这个数看着有点紧，时间和金额都可以再调整」，并给出「把时间放长一点 / 先少存一点」两条现成的路。

**只说「你要放多少」就是在催她**，所以必须给出方向。

**第七步 · 分罐子与确认**
四个罐子生成，可直接改数字。改过才算数，确认后才写入状态，所有后续回答只读已确认值。

全程可跳过、可回改。填错了随时能改。

## 三、日常使用的三个入口

首页第一视觉是小狗，不是报表。点小狗后它先开口一句，下面挂两个气泡；也可以直接打字。气泡是降低表达成本，不是功能菜单。

### 帮我看看要不要买

流程：读取安心罐余额 → 最多追问一句 → 三个中性动作 → 约定回看。

**硬规则：可自由支配的钱 = 安心罐。生活罐的钱永不计入「可以买」的额度。**

这条规则从根上防止了「生活罐还有 2300，所以 400 的 T 恤放得下」这类误判，也因此不需要在生活罐内部再做水位线分层。它和「安心罐就是可以安心花的钱」这个定义天然一致。

安心罐不够时，只陈述差额并把选择权交回去：

> 按安心罐算会差 280 元。剩下这部分你想放在哪里？

差额部分由你明确选择来源：可从梦想罐出，或从生活罐出（按钮上直接标明生活罐最多能出多少）。**绝不自动从别的罐子扣。**

自动级联等于系统替用户决定「当下消费优先于未来目标」，会破坏信任，也与「用户改过才算数」冲突。

**三个动作**

| 动作 | 行为 |
|---|---|
| 现在买 | 记录决定，回看时确认是否实际发生并更新罐子 |
| 放到明天 | 创建用户同意的回看时间（一天或三天），提醒可关闭 |
| 这次先不买 | 同样进入回看，不能被庆祝为更好的选择 |

三者视觉上完全一致：同字号、同颜色、同下划线，没有主按钮、没有推荐标记。「这次先不买」不会被表扬，到了约定的回看时间照样来问你「后来呢」。

回应硬约束：最多三句；一次只问一件事；不解释自己正在执行什么流程；**先回应情绪，再引用数字**——顺序反了就会变成带关心口吻的审计。

### 记一笔钱

先问金额，默认建议安心罐但不直接执行，你可以换罐，一键确认后才修改状态。**绝不在某个罐子不足时静默继续扣另一个罐子。** 没有明确消费发生、只是表达情绪时不扣钱，保留「只说说，不改余额」。

不要求记全、不追分类、不补漏。

### 有一笔钱想和你聊一聊

先接情绪，不追问用途，不给建议。最后给你两个选择：帮你记下来，或者只是聊聊、不改余额。

这个入口的存在是因为：不是每次想找慢慢都是为了解决具体问题。有时候就是发了工资、就是花超了想说一句、就是想戳一下它。

## 四、四个罐子

| 罐子 | 回答的问题 | 数量 | 跨周期 |
|---|---|---|---|
| 生活罐 | 这个月必须怎样活下去 | 1 | 每周期重新安排 |
| 安心罐 | 这个月我愿意给自己多少自由 | 1 | 每周期重新安排，是恒等式余数所在 |
| 梦想罐 | 我正在为哪件具体的事攒钱 | 1，用户命名 | 累计不清零，由目标倒推月供 |
| 未来罐 | 有多少钱暂时不准备花 | 1 | 长期累计，默认 0，只能用户主动填 |

一句话概括：生活罐照顾责任，安心罐允许快乐，梦想罐实现具体愿望，未来罐让一部分钱长期留下。

### 恒等式

```
生活.planned + 安心.planned + 梦想月供 + 未来.planned = 本月可安排金额

余数   → 安心罐
未来罐 → 默认 0，永不自动接收
```

**为什么余数不能进未来罐：** 那等于产品默默说「剩下的钱应该存起来」，是「不月光=好」的变体。慢慢不预设「存钱=好」，也不预设「花钱=坏」。

### 不强迫四个罐子都有钱

合法结果包括：这个月收入紧张，只有生活罐和少量安心罐；没有具体目标，梦想罐暂不开启；暂时不想长期储蓄，未来罐为 0；这个月主动选择多享受生活，安心罐最大。

**没有哪个罐子更高尚。** 界面上没有完成度、没有百分比、没有红色超支提示，也没有连续签到和「你已经几天没来」。

### 结余碎钻

上期没花完的钱不挂在任何罐子名下，单独显示成一小堆碎钻。它就是一笔还没安排的钱——不属于任何罐子，所以不需要为它编一个语义。

三条视觉约束：
- 一小堆碎钻，不是一颗大钻石。低饱和、弱高光、不闪烁
- 大小分三档（小/中/大），不做线性放大
- 为 0 时不显示

三条动效约束：
- 变多时不庆祝（不发光、不弹窗、不说「又攒下一颗」）
- 不计数（没有「你有 12 颗」，没有角标红点）
- 变少时不失落，小狗不垂耳朵

**为什么是一堆碎钻而不是一颗大钻石：** 一颗大钻石被拿走一块像损坏，一堆碎钻里挪走几颗只是用掉了一些余地。而结余挪进罐子本来就是好事——意味着这个月更宽裕。挪走时慢慢会说「好，这个月就松一点了」，把变少明确说成好事。

**为什么不自动转入未来罐：** 留在原地没有发生状态变化；自动转走是一次未经确认的跨罐移动。钱不动不需要确认，钱动了就需要。

## 五、回看与金钱原则

每一种决定都可以产生回看：现在买、延后和不买没有高下。回看关注「实际发生了什么」「哪笔花得最值」「哪笔与原安排差别最大」，而不是统计用户忍住了多少次。

### 七步链路

| 步 | 动作 | 约束 |
|---|---|---|
| 1 | 触发 | ≥3 条已完成回看的故事。不是 3 次决定，必须有结果 |
| 2 | 检索 | 取 3 条故事 ＋ 已确认原则（防重复） |
| 3 | 生成 | 1 条候选 ＋ evidenceIds |
| 4 | 校验 | 违禁词 / ≤25 字 / 第一人称 / evidenceIds 非空 / JSON Schema。失败重试一次 |
| 5 | 展示 | 卡片 ＋ 依据可展开看到那三条故事 |
| 6 | 确认 | 像我 / 改说法 / 暂不确定。只有确认或修改后才 confirmed |
| 7 | 引用 | 折叠显示「参考了：1 条你确认过的原则」，可展开 |

### 两条容易漏的规则

**冲突不覆盖。** 新原则与旧的矛盾时两条都留、标上时间，由用户选保留哪条。

**校验失败就不提。** 一条像贴标签的原则，伤害比没有原则大得多。

### 示例

> 我不是舍不得花钱，是要先看见它会不会进入生活。

只有用户确认或修改后，才可以参与后续回应。

### 原则的两个来源

**一是行为。** 三条已完成回看的选择，能看出你的倾向，比如「我放一晚再决定，好像更踏实」。

**二是你自己的话。** 你在「有一笔钱想和你聊一聊」里讲的每一句，慢慢都记着。

它不会追问「你当时为什么想花这笔钱」——那会把闲聊变成问卷，也违背「立即接住，不追问」这条语气规则。它只是从你自然说出的话里留意场景：「同事临时约」「刷到一个」「一直想着」，是三种完全不同的动心方式。

这类记忆能支撑行为数据推不出的原则。比如「我在朋友在场的时候容易动心」——光看买没买是看不出来的。

所有依据都可展开。**慢慢不追问，但也不背着你记。**

本期实现了第一条。第二条的实现涉及 MCP 输出 schema 变更、新增入模字符串的安全扫描、以及原则生成 prompt 的输出分布重测，排在复赛。

## 六、MCP 调用

```
Endpoint  https://bondpup.vercel.app/mcp
传输      Streamable HTTP，仅 POST
协议版本  2026-07-28(兼容 2025-era 旧版)
```

### 推荐调用顺序

1. `server/discover` — 读取支持的协议版本、capabilities 和 serverInfo
2. `tools/list` — 确认 5 个工具的描述、输入/输出 schema
3. `create_money_session` — 创建匿名 demo 会话
4. `plan_jars` — 四罐分配，默认只预览，`confirm:true` 才写入
5. `record_money_moment` — 说一笔想花的钱（如「我想买一件衣服，但有点愧疚」），返回带签名的 proposal，检查语气与候选动作
6. `confirm_action` — 用户确认后写入，检查 stateVersion 递增与原则卡生成
7. `get_money_overview` — 总览四罐、待回看、候选原则、周期回顾、结余历史

### 本地冒烟

```bash
node scripts/smoke-mcp.mjs https://bondpup.vercel.app
```

### 架构约束

网页 API 与 MCP 调用**同一套领域服务、同一个计算器、同一份安全规则**。金额逻辑不复制，MCP 工具直接包装既有的确定性函数。

所有金额字段使用以分为单位的整数（`minimum: 0`），展示层再除 100，避免浮点加法导致「四罐合计 = availableAmount」对不上。

读工具不改变状态；写操作一律要求 `expectedStateVersion` 与 `idempotencyKey`，版本不符拒绝、重放幂等；`confirm_action` 只接受 `record_money_moment` 签发的 proposal，伪造签名会被拒绝。

会话匿名、服务端不持久化状态：每个响应回传完整 `moneyState`，客户端原样链回即可，不暴露任何真实用户数据。

## 八、边界与安全

### 计算与状态

金额一律由确定性代码计算，模型只负责理解语言和组织短回应。任何会改变罐子状态的操作都需要用户显式确认。跨罐永不自动级联。

代码负责：月供、罐子总和、跨罐影响、目标延期、余额新鲜度、纯加法清单求和、幂等、回看调度、碎钻拆分、违禁词、句数、JSON Schema、安全硬红线。

模型负责：识别用户处境、金额候选和情绪线索、生成最多一句追问和三句以内回应、把模糊愿望翻译成可修改的「在意的事」、基于证据生成一条候选原则。

### 明确不做

投资建议、银行连接、自动读取账单、信用或借贷产品、多目标管理、泛化情感陪伴。

### 安全响应

| 风险 | 响应 |
|---|---|
| 自伤、绝望、严重困扰 | 停止理财话题，表达关心，给出 24 小时心理援助热线 12356，进入安全退出界面 |
| 债务、借钱、分期、网贷 | 不提供还款策略和借贷推荐，提示超出范围 |
| 投资 | 完全不做。未来罐用途标签只有安全垫 / 长期储蓄 / 暂未决定，不记投入额、不显示市值、不推荐任何产品 |
| 泛化情绪问题 | 听一句，不追问细节，仅询问是否影响当前金钱安排 |
| 隐瞒关系 | 不主动引导用户对家人、伴侣或机构隐瞒 |

### 禁用词

由代码层校验（输出闸 + CI 静态文案扫描），共 20 个，不只靠提示词约束：

```
超支  赤字  超标  不够  没存够  太多了  太少了
应该  必须  你最好  建议你  加油
比上次好  比之前强  比原地不动厉害
你真棒  你很厉害  你好优秀
月光族  值不值
```

### 合规

本次体验限定 18 岁以上，不提供虚拟亲密关系或消费诱导。界面持续提示正在与 AI 互动。连续使用每超过 2 小时提醒注意使用时长。提供便捷退出途径，支持数据复制（导出）与删除。

### 数据表述

产品自身不在服务端持久化完整聊天记录；完成当前回应所需的最小摘要会经 Serverless Function 发送给模型提供商。

localStorage 只保存必要的结构化状态与短摘要，不保存真实姓名、身份证、银行账户或完整倾诉原文。命中安全红线的输入不会发给模型，审计事件只记风险类型，不含用户原文。
