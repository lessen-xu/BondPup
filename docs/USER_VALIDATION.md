# 用户验证记录

## 需求起点:一个具体的人

这个产品从**共同创作者自己**开始——她刚拿到人生第一份工资,试过记账 App,很快卸载了:预算红字和「超支」提示在替她评判什么是该花的,而她需要的不是被管着,是一个能商量、不带脸色的对象。

她既是第一个用户,也是设计者:四个罐子的名字、「三个中性动作」、「回看只问后来呢」——都是先在她自己身上试,觉得不刺人了才定下来。**用户参与设计不是这个项目的弱点,而是它成立的方式。**(本节表述由本人确认。)

**推及的相似人群**:同样刚拿到第一份工资、对「被评判」敏感、想跟钱和解而不是被管教的年轻人。

**核心假设**:这个人群缺的不是记账工具,而是一个不评判的对象——传统记账应用的「超支红字」「预算完成度」本身就是劝退的来源。所以产品的可验证主张是:

1. 全程没有「超支/不够/应该」类评判语言,判断权始终在用户手里
2. 决策是三个中性并列动作(现在买/放到明天/这次先不买),不问「值不值」、不预选
3. 数字为 0 也不隐藏、不标红——0 元只是一个事实

## 已完成的验证

### 真实用户实测:创作者的母亲(2026-08-09,线上生产环境)

一位完全没有参与开发、也不了解产品设定的真实用户,独立走了从零开始的完整起点流程,暴露出四个创作者自己永远发现不了的问题,当天全部修复上线:

1. 「这个月能安排多少钱」被她理解成「能存下来多少」——问法改成直接问收入
2. 目标金额填 50 万、月收入 1.5 万,月供算出 41667 元把四罐撑爆、按钮禁用,流程卡死——增加「把时间放长 / 先少存一点」两条继续路径
3. 「500万」这样的中文数字输不进去——金额输入增加中文单位解析
4. 选「这个月先不留」后四罐合计不变的计算错误——已修

她不属于目标画像(非第一份工资),因此这次实测验证的是**可用性与流程健壮性**,不作为目标人群共鸣的证据;但「真实使用 → 具体反馈 → 当天修复」这条链路是完整且可查证的(对应仓库 PR 记录)。

### 语气红线的机器化验证(持续生效)

语气规范不靠自觉,靠两道闸(见 [ARCHITECTURE.md](ARCHITECTURE.md)):20 个禁用词 + 句数上限硬校验,违规重试后兜底;CI 里另有静态文案扫描,写死的 UI 文案命中禁用词即红灯。真实模型上线当天即拦下真实违规样本(模型问「值不值」、4 句长回复),证明闸门在真实分布上有效,记录见 [EVALUATION.md](EVALUATION.md)。

**当前结论(区分层次)**:服务端 `/api/agent` 已验证正确——四类全部命中、输入不发给模型、自伤类返回带 24 小时心理援助热线(12356)的固定文案与 `crisis` 分流标记,契约测试锁定。

网页展示层当时暴露的两个问题——热线被硬编码文案覆盖、首次提交尚未请求安全接口(需再点一次才分流)——均已修复合入。**端到端已达标**:2026-08-10 对生产环境跑 `npm run verify:browser`,第 1 条「危机输入首次提交即进安全出口并原样展示热线 12356」通过,且未退回普通陪聊文案、控制台零错误。

### 起点流程复测(2026-08-11,复赛阶段)

创作者复测问卷流程时发现:填了梦想罐目标(如「买一件 hcb」,月供已单列)后,分配屏的「安心罐这些就是留给它们的」仍把该目标对应的在意事项列在内——目标的钱在梦想罐,这句归属表述是错的。当天修复:安心罐归属文案排除已成为梦想罐目标的条目(含「一件/那件」这类量词变体的匹配),存入偏好的完整列表不受影响,带 7 项单元测试。

### 外部用户测试(2026-08-12,复赛阶段,生产环境)

两位未参与开发的真实用户,由共同创作者引导但不代填,各自独立走完起点流程。

**用户一(朋友)发现一个金额确定性 bug**:目标填「存 30000 元去日本,12 个月」,拆解出的「在意的事」变成「12 个月攒到 300万日元」——数字和货币都是模型编的。根因:目标金额以分为单位的原始整数(3,000,000)被直接放进了 prompt,模型读到 3000000 写成「300万」,再从「日本」联想出「日元」。当天三层修复:①金额先换算成元的展示文本再进 prompt(与对话路径同规则);②拆解指令加数字铁律;③**输出闸新增数字保真校验**——输出里的数字必须能在输入里找到(「3万」与「30000」互认),输入没有的货币词一律拒绝,不合格重试一次后走确定性兜底。带 6 项回归测试,其中主用例就是这条真实输入。

**用户二完成七问回访**,原话摘录:
- 流程清晰度:「几乎都能填,挺清晰的,陪伴型存钱」;全程没觉得被教育或心虚
- 三个动作:「没觉得哪个更对」——但提出「现在买/放到明天」的区分感知不强,更自然的分法可能是「现在买/下次买/下个月买」(设计层反馈,复赛评估)
- 语气原话:「没觉得像 ai,觉得像 sdw 说话哈哈哈哈哈哈但是有猜到应该是 ai」(sdw 为共同创作者名字缩写——像作者本人在说话,而作者正是产品语气的定稿者)
- 最想改的一处:「生活罐是一下子填掉的,怎么确定我就需要这么多?」——纯加法清单入口存在但她没有发现,可发现性待改进(界面层反馈,复赛评估)
- 如实记录:她自述可能不是核心受众(「我可能只需要记账功能」),认为产品特点在「小狗聊天、看要不要买」
- 收入边界复测(同一用户,两轮):第一轮月收入填 2,505 时安心罐所剩极少,核心机制几乎无法触发,对应上面「只需要记账功能」的自述;第二轮改填 11,000 后反馈「挺清晰的」「安心罐也好用」「感觉这么用确实能攒很多钱」——产品适配的是「有一点选择空间」的阶段,低可支配收入下的体验边界如实记录

### 外部用户测试·用户三(2026-08-13,复赛阶段,生产环境)

第三位未参与开发的真实用户独立走完起点流程,第一印象是「新的体验,可能是和钱有关的东西」。反馈分三类处理:

**当天修复(界面可用性)**:
1. 「按钮选中的颜色很不明显」——问卷选项选中态原来只靠透明度差(0.74→1),纸纹按钮上几乎看不出;选中态增加描边圈
2. 「小字太小了」——流程提示类小字整体上调一档(最小 11px→12px)
3. 「说给我听——我是谁?」——按钮文案「说给我听」里的「我」指小狗,但用户读成了自己;改为带狗名的「说给{狗名}听」,三处使用点统一

**当场核对、无需改动**:
- 「很多都选择跳过会不会影响后续使用?」——不会坏:所有对话流程都有无状态兜底(没分罐子也能聊,只是不能报余额);跳过只会减少个性化(在意的事、原则的素材变少)。此点已由契约与流程测试覆盖。

**提出时记为设计层、复赛阶段已修复**:
- 目标金额想填一个范围(如 3k–5k),不确定要多少钱 → 金额解析支持区间(取中间值并回显说明)、「三千多」类模糊表述与 k/w 后缀(#81,2026-08-13)
- 未来罐是什么——希望在看到它之前先有一句解释 → 改为先解释再询问是否留存(#83,2026-08-13)

**设计层反馈(复赛评估,不当天动)**:
- 有好几个愿望,但最后只能写一个(目标只支持单个)
- 问卷过程中希望能和小狗互动;「击掌」希望有真实的击掌反馈动效
- 想再多加一个自定义罐子
- 想要语音输入
- 气泡位置偏上(转交共同创作者视觉调整)

### 目标画像用户测试·用户四(2026-08-13,复赛阶段,生产环境)

**第一位目标画像用户**(共同创作者招募,第一份工资人群),独立走完起点流程后完成八问回访 + 第一屏五秒测试。原话摘录:

**第一屏五秒测试**:「有点像电子宠物陪伴」,下一步自发点了小狗——入口可发现性通过,产品第一印象与定位(陪伴而非工具)一致。

**核心主张的验证**:
- 卡点(①):四个罐子出现时停下来「重新理了下钱的分配」——是产品促发的主动思考,不是流程障碍
- 评判感(②):「工资太少所以心虚」——心虚来自工资本身,**不是产品语言**;全程没觉得被教育
- 语气(④):没有觉得假或 AI 的句子
- 会再打开吗(⑦):「会,可能我需要买高价值非硬需求的东西时会问一下」——**这正是产品设计的核心场景(决策陪伴),被目标用户自发说出**

**如实记录的偏差信号(③)**:「这次先不买」在她看来是"更对的"选项。三个动作的样式、顺序、文案已多轮机器验证完全中性(无预选/无推荐/样式一致),这一感知更可能来自用户自身的节俭倾向,但仍如实记录——中性呈现不等于中性感知,复赛阶段继续观察其他用户是否有同样感知。

**概念模型反馈(⑥⑧,设计层,复赛评估)**:
- 「梦想罐最有用,安心罐有点多余——安心罐的支出通常从我的生活和梦想罐里来」
- 最想改:梦想罐——「对我来说不是硬性要求,是可以机动性支出的」
- 两条指向同一件事:她的心智里「弹性支出」和「目标储蓄」的边界与四罐模型不同。四罐语义本期冻结,此反馈进入复赛后的模型讨论

后续:该用户反馈仍在继续收集,如有可修项将追加「反馈→修复」记录。
