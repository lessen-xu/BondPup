# 架构说明

## 分层

```
src/contracts/   数据契约(zod):MoneyState、罐子、故事、原则、错误码 —— 全仓唯一事实源
src/server/domain/   确定性计算:四罐恒等式、月供重算、扣罐/撤销、周期切换、结余、原则状态机
src/server/safety/   安全层:输入闸(风险分流)、输出闸(禁用词/句数)、原则校验
src/server/agent/    模型任务层:prompt 构造、provider 选择与降级、确定性 Mock
src/server/mcp/      MCP 工具面(5 个工具),包装 domain 层
src/app/             页面与 API 路由(/、/api/agent、/mcp、/health)
src/lib/             前端侧共享:计划计算、演示数据、agent 客户端
```

依赖方向自上而下单向:页面 → lib/domain → contracts;agent/mcp → domain → contracts。contracts 不依赖任何层。

## 三条不变式

1. **金额由代码计算,理由由模型生成。** 所有金额运算都在 domain 层的确定性纯函数里,单位一律「分」(整数);模型的 prompt 里只出现已由代码格式化好的展示文本(如「3500 元」),并被明确指示原样引用、不做任何换算。模型永远碰不到算术。
2. **改变状态必须用户确认。** 一切写操作走「预览 → 确认」两段式;确认必须带 `expectedStateVersion`(乐观锁)与 `idempotencyKey`(幂等),重放安全。
3. **跨罐永不自动级联。** 任何一个罐子的变动不会自动引起另一个罐子变动;结余、挪动都是用户显式发起。

## 为什么域计算可以在浏览器里执行

页面直接 import domain/lib 的计算函数,在浏览器内对 localStorage 里的状态执行。这是有意为之,不是妥协:

- **不变式 1 约束的是「谁来算」(确定性代码 vs 模型),不是「在哪算」(服务器 vs 客户端)。** 同一套函数被 MCP 工具面在服务端原样执行,两处结果必然一致——纯函数没有环境依赖。
- **数据默认不出本机。** 用户金钱状态只存浏览器 localStorage,本地执行意味着日常操作零网络依赖、零延迟、离线可用,也是隐私的最短路径(见 [PRIVACY.md](PRIVACY.md))。
- **没有可攻击的多方状态。** 无账号体系、无排行榜、无共享数据,用户"篡改"的只能是自己浏览器里自己的数据。真正需要防伪造的只有跨请求传递的候选动作(proposal),它由服务端 HMAC 签发并验签(见 [MCP.md](MCP.md))。

## 模型层:provider 选择与降级

```
ANTHROPIC_API_KEY 存在        → Anthropic 原生(claude-sonnet-5)
OPENAI_COMPAT_* 三件套存在    → OpenAI 兼容端点(当前:DeepSeek v4-flash)
都没有 / 调用失败 / 超时       → 确定性 Mock(评测「无密钥可跑」,也是降级路径)
```

- 单次调用预算 8 秒,provider 层不重试;失败即降级 Mock,体验不断,降级原因入日志(不含用户输入)。
- 客户端默认超时 10 秒 > 服务端 8 秒:网页放弃时服务端一定已结束,不产生白计费。
- DeepSeek 默认开思考模式,复杂 JSON 任务会长考近千 reasoning token(实测 9.2s);对 deepseek 端点显式关闭 thinking 后 1.4s。
- 成本护栏:`max_tokens: 1000`;公开只读的 MCP `get_money_overview` 里候选原则固定用确定性 Mock 生成,真实模型额度只服务产品内交互;`/api/agent` 每 IP 每分钟 30 次限流。

## 安全层:两道闸

**输入闸**(调模型之前):关键词分流四类风险——自伤(进安全出口,带心理援助热线)、借贷、投资、泛化情绪。命中即绕过模型返回固定安全回应,0.02s,零模型调用;审计事件不含用户原文。匹配前做 NFKC 归一化并去空白标点,变体(「不 想,活」)也命中。

**输出闸**(模型回来之后):禁用词表(超支/应该/加油/值不值……共 20 个)+ 句数 ≤3(全角半角标点都算句读)。写死的 UI 文案同样受管:CI 里有静态文案扫描(`npm run scan:copy`),对用户可见的字符串命中禁用词即红灯。不合格自动重试一次,再不合格用安全兜底文案——违规文本永远出不了门。候选原则另有更严校验(≤25 码点、第一人称、证据可追溯),失败重试一次后静默放弃:一条像贴标签的原则,伤害比没有原则大。

这两道闸在真实模型上线当天的实测里各拦下过真实违规样本(4 句全角标点回复、「值不值」判断性提问),详见 [EVALUATION.md](EVALUATION.md)。

## 能力覆盖范围(网页 / MCP)

两个面共用同一套 domain 计算,但接入进度不同,文档不代表网页已完成:

| 能力 | 网页 | MCP |
|---|---|---|
| 四罐分配、扣罐/撤销、决策故事、回看 | ✅ | ✅ |
| 候选原则生成→确认→引用 | 生成校验已统一到服务端编排,页面接入验证中 | ✅ |
| 跨周期 CYCLE_REVIEW(月供重算、结余结转) | ❌ 后续接入 | ✅ |
| 结余碎钻挪动(moveLeftover) | ❌ 后续接入 | ✅ |

## 状态模型

`MoneyState` 是唯一状态对象:罐子数组(有周期必四罐,0 元也保留,schema 强制)、决策故事、原则、结余、安全事件审计、`stateVersion`、`appliedOps`(幂等键环形记录)。所有写操作:版本不匹配 → `state_conflict`;幂等键重放 → 返回首次结果不重复写。MCP 面无状态服务化:每个响应回传完整 `moneyState`,客户端链回,跨实例无共享存储依赖。
